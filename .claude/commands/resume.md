作業を再開します。ワークスペース配下のメモリを読み込んで前回の文脈を把握してください。

## 手順

1. `.memory/MEMORY.md`（リポジトリルート直下）を読む。これが索引。無ければ記憶はまだ無いので、手順3へ進む。
2. **必要なメモリファイルだけを開く**（全件は開かない）。
   - **常に読む**: `user_profile.md` と `feedback_*.md`。作業内容によらず「進め方」を規定するため。
   - **選んで読む**: `project_*.md` / `reference_*.md` は、**再開する作業に関係するものだけ**。
     判断材料が無ければ、現在のブランチ名・直近のコミット・`git status` から推測する。
     それでも絞れなければ、**どの作業を再開するかユーザーに尋ねてから**開く。
   - 開かなかったファイルは、**必要になった時点で開けばよい**。索引の一行で足りることも多い。
3. 必要に応じて `git log --oneline -10` と `git status` を確認し、メモリの記載と実際のリポジトリ状態にズレがないか突き合わせる（メモリが古い場合は実態を優先する）。
4. 以下を簡潔にまとめて報告する：
   - **現在地**：直近で完了したこと
   - **次の作業候補**：順当な次フェーズ
   - **未決論点 / 残作業**：あれば列挙
5. 「どこから再開しますか？」とユーザーに確認する。

メモリの種類・保存先のルールは `CLAUDE.md` の「セッション記憶（Memory）」セクションに従うこと。

> **なぜ全件読まないか**: メモリ全体は放っておくと膨らみ、再開のたびにコンテキストを圧迫する。
> 索引を読んで必要なものだけ開けば、再開に必要な文脈は十分に得られる。
> 恒久的な規約・構成の実態は `docs/` が正本なので、詳細はそちらを参照すればよい。
