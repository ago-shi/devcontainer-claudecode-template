ユーザーがツール・ライブラリ・技術について質問し、Claude が説明を行った場合、会話の最後に次を確認する：

> 「この説明を `docs/knowledge/` に記録しますか？」

ユーザーが記録すると回答したら、以下の手順で進める。

## ファイル命名規則

- 基本は **ツール名**（例: `docker.md` / `git.md`）。ツールに紐づかない横断的な内容は **トピック名**（例: `networking.md` / `devcontainer-git-auth.md`）。
- **新規ファイルを作る前に必ず既存ファイル一覧（`docs/knowledge/README.md` の索引 or Glob）を確認**し、既存のツール/トピックに収まるならそこへ追記する（類似名の乱立を防ぐ）。

## 手順

1. **記録前に重複チェックを `doc-reviewer` サブエージェント（モードB）へ委譲する**（メインのコンテキスト節約）。
   - Task ツールで `doc-reviewer` を起動し、記録先ファイル名（`docs/knowledge/<ツール名 or トピック名>.md`）と追記しようとしている内容の要約を渡す。
   - サブエージェントは既存ファイルを自ら読み、「既出（重複）」「新規（記録価値あり）」「推奨アクション（新規作成 / 差分のみ追記 / 既存節の更新 / 記録不要）」を短い報告で返す。
2. **報告に従って記録する**（書き込みはメインが行う。サブエージェントは読み取り専用）。
   - 新規にすべき差分のみを対象ファイルに追記する。ファイルが無ければ新規作成。
   - 全部重複なら記録しない。
3. **新規ファイルを作成した場合は `docs/knowledge/README.md` の索引に1行追加する**（`- [ファイル名](file.md) — 概要`）。README.md が無ければ作成する。
4. 記録する内容は、説明した概念・仕組み・ハマりどころ・判断の理由など、**将来見返したときに価値のある情報に絞る**。
